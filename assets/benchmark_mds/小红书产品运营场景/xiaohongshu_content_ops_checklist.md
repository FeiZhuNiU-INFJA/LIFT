# 小红书内容运营评测数据集 Checklist

## 一、结构合规性

- [x] 任务类名明确：小红书内容运营
- [x] 每个任务独立成目录，且目录名等于 Markdown 文件 basename：q1_single_product_note/q1_single_product_note.md、q2_multi_product_combo/q2_multi_product_combo.md、q3_competitor_diff/q3_competitor_diff.md、q4_data_driven_optimize/q4_data_driven_optimize.md、q5_campaign_content_matrix/q5_campaign_content_matrix.md、q6_final_comprehensive/q6_final_comprehensive.md
- [x] 每个任务只包含一个 Markdown 文件
- [x] 每个任务目录都包含 materials 文件夹
- [x] 每个任务 Markdown 只包含三个三级标题：query、要求、轨迹要求
- [x] 不存在材料来源、结果文件等额外任务标题
- [x] query 不展开要求细节，但包含工作区 materials 和 result/result_q{n} 文件夹说明
- [x] 要求覆盖所有内容需求、业务需求、格式需求、约束需求和个性化需求
- [x] 轨迹要求与要求不矛盾，可补充必要轨迹要求
- [x] 产出文件保存位置统一为工作区 result/result_q{n} 文件夹，不强制文件名
- [ ] 如新增 skill，根目录包含 skills 文件夹且每个 skill 至少包含 SKILL.md（本数据集无需新增 skill，不适用）

## 二、难度递进

- [x] Q1→Q2 递进关系明确：单品笔记 → 多品合集，维度扩展（选品+搭配逻辑）
- [x] Q2→Q3 递进关系明确：多品合集 → 竞品分析+差异化策略，场景升级（引入竞品对比维度）
- [x] Q3→Q4 递进关系明确：竞品分析 → 数据驱动优化，能力组合（数据分析+内容优化）
- [x] Q4→Q5 递进关系明确：数据优化 → 活动策划+内容矩阵，复杂度提升（多KOL+排期+投流）
- [x] Q5→Q6 递进关系明确：活动策划 → 综合测试，能力组合（数据分析+竞品分析+活动策划+策略规划）
- [x] 最终测试Q6综合性最强：组合了数据分析、竞品分析、活动策划、内容生成、策略规划5个能力维度
- [x] 整体难度曲线平滑无突变

## 三、最终测试任务专项

- [x] Q6组合至少3个之前任务的能力维度：数据分析（Q4）、竞品分析（Q3）、活动策划（Q5）、内容生成（Q1/Q2）、策略规划（Q5）
- [x] Q6 query口语化/模糊化："这几个事帮我一起搞了吧，看着做就行"
- [x] Q6要求数量（15条）不少于Q1-Q5中任何一个任务（Q1:10, Q2:11, Q3:8, Q4:8, Q5:11）
- [x] Q6需要Agent自主判断进行哪些操作：query未指定具体分析维度、优化方向、差异化策略，需Agent自主判断

## 四、要求设计

- [x] 内容要求有明确约束：品牌调性、文案风格、合规标注、禁止用语
- [x] 轨迹要求有明确约束：采用"操作类型+目的"描述，如"需进行数据解析操作，读取...提取...为...提供依据"
- [x] 同类任务间要求可增减不冲突：Q1单品→Q2多品增加合集逻辑，Q3增加竞品分析维度，Q4增加数据分析维度，Q5增加排期和投流
- [x] 存在私人定制化要求：品牌调性约束（北欧简约温暖治愈）、目标受众偏好（25-35岁都市女性）、KOL定制内容方向
- [x] 核心约束贯穿所有任务：广告法合规（禁用绝对化用语）、平台规范（带货标注）、品牌调性一致性

## 五、场景真实性

- [x] 符合真实业务场景：小红书内容运营是真实存在的办公场景，非调研/分析类
- [x] 用户画像合理且一致：林悦，栖居品牌内容运营负责人，贯穿Q1-Q6
- [x] 可用接口假设合理：浏览器操作工具（浏览竞品笔记/平台趋势）、商品库接口、数据分析接口、图片生成接口、笔记发布接口
- [x] 决策点符合真实业务逻辑：选品决策、差异化定位、数据驱动优化、活动排期、投流分配

## 六、进化学习能力验证

- [x] 前期任务显式提示轨迹：Q1明确要求"需进行数据解析操作""需进行内容生成操作""需进行可视化设计操作"
- [x] 后期依赖Agent学习：Q6的轨迹要求更综合，Agent需自主判断先做什么后做什么、各分析维度如何关联
